# Проброс портов для друзей

Друг подключается **не к MySQL**, а к двум игровым портам. На роутере / в cloud-firewall пробросьте **TCP** с внешнего IP ВМ:

| Порт | Сервис | Обязателен |
|------|--------|------------|
| **3724** | authserver (логин, список реалмов) | да |
| **8085** | worldserver (сам мир) | да |

Других портов для игры нет. 3306 (MySQL) **не** открывайте наружу.

## Что сделать на сервере

1. `BindIP = "0.0.0.0"` уже проставлен скриптами — слушаем все интерфейсы.
2. Прописать **внешний** IP (или DNS) в таблицу реалма, иначе клиент друга после логина пойдёт на 127.0.0.1:

```bash
scripts/set-realm-address.sh playerbots 203.0.113.10
```

Подставьте ваш вариант (`npcbots` / `lonewolf`) и публичный адрес.

3. UFW (если включён):

```bash
sudo ufw allow 3724/tcp
sudo ufw allow 8085/tcp
sudo ufw reload
```

## Что сделать другу

В клиенте 3.3.5a ruRU (на Bazzite — файл внутри Proton/Wine prefix) `Data/ruRU/realmlist.wtf`:

```
set realmlist 203.0.113.10
```

Аккаунт создаёте вы на сервере (`account create ...`) и отдаёте логин/пароль. Регистрации через сайт в этом наборе нет.

## NAT / «играю с той же сети»

- Друг в той же LAN: в realmlist внутренний IP ВМ (`192.168.x.x`), проброс на роутере не нужен.
- Вы дома, друг из интернета: проброс 3724 и 8085 на LAN-IP ВМ, в `realmlist` и `set-realm-address` — **белый** IP (или Tailscale/ZeroTier-адрес, если играете через mesh без проброса).
- Если провайдер за CGNAT и белого IP нет — Tailscale/WireGuard всем участникам, адрес реалма = IP mesh.

## Одновременно несколько вариантов

По умолчанию все три стека хотят 3724/8085, systemd-юниты конфликтуют. Для двух миров сразу смените в конфиге второго стека `RealmServerPort` / `WorldServerPort` и поле `port` в `realmlist`, затем пробросьте уже **эти** порты. Для «позвать двух друзей» достаточно одного варианта.
